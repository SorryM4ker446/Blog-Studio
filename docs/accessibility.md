# Mobile layout and keyboard access

At viewport widths of 768 CSS pixels or less, navigation uses a temporary modal drawer. Its open state is separate from the desktop sidebar Cookie. Opening, closing or resizing the drawer does not change the desktop collapse preference. The drawer supports its close button, backdrop, Escape and a Tab/Shift+Tab focus loop. The browser makes the background inactive while the drawer is modal.

Navigation closes the drawer after the destination URL has committed. An unsaved-editor confirmation opens above it; cancellation preserves the editor URL, text, drawer and focused link. Closing normally returns focus to the menu button. Moving to desktop layout or completing ordinary page navigation focuses main content without forcing a scroll. Browser history traversal retains the existing scroll restoration; search/query updates retain input focus. A visible-on-focus “Skip to main content” link bypasses the sidebar.

Layouts use dynamic viewport height and safe-area padding. Editor actions wrap on narrow screens, and Markdown input and preview stack vertically. The desktop editor retains its expanded-sidebar width budget. Long prose and links wrap; code blocks and tables can scroll locally and receive keyboard focus. Homepage link cards are interactive. Settings uses explicit buttons to open profile and password dialogs; closing a dialog returns focus to its trigger.

Sidebar More/Less controls animate the extra category rows with a reversible height and opacity transition. Collapsed extra links remain inactive, and the control retains keyboard focus. A collapsed list shows only three interactive categories; remaining rows stay clipped and inactive. More and Less are matching left-aligned ghost rows on the category text baseline, with the same muted text color and no selected background or decorative preview. Hover and keyboard focus use the accent color. The control position and size remain stable while its chevron rotates; mobile controls retain larger touch targets. Search keyword and category changes share the scope transition: old results stay visible while loading, then exit before the new results enter; paging keeps its independent transition. The first search keeps its loading status visually hidden and available to screen readers; results enter directly when ready. Reduced motion displays the results without animation.

Main and footer navigation entries expose the current section with a shared highlight and `aria-current`. The Posts Playground home link retains current-page semantics without a selected background. Article detail retains its source section (including a selected category); direct article entry defaults to All Posts. Editor detail belongs to Content Editor. Query changes retain selection; client navigation and browser history update it in both desktop and mobile navigation.

Category selection supports arrow keys, Home/End, Enter and Escape. When management is available, Tab moves from the open selector to the selected category's rename/delete actions; these actions are outside the listbox options. Tab out closes the menu. Creation and successful renaming return focus after the loading controls become available. Resource tabs use one Tab stop, Left/Right to change selection and Home/End to select the first/last tab.

The Markdown label targets the actual textarea. A small adapter supplies accessible names and keyboard activation for the existing editor library's span-based toolbar, heading/table pickers and image input. It relies on that library's DOM classes, so dependency upgrades must rerun the keyboard and accessibility browser tests. The shared Markdown parser adds `loading="lazy"` and `decoding="async"` to body images while preserving supplied dimensions, escaped HTML and safe-link validation. First-screen identity avatars retain their existing loading behavior.

The reduced-motion preference disables CSS animations and transitions across the shell, dialogs, skeletons and inline styles; result and sidebar animation modules also honor it. Drawer display/overlay transitions progressively enhance browsers supporting discrete transitions; older browsers still open and close the native dialog. Browser-owned refresh/close warnings remain outside application styling and are not guaranteed on forced termination.

After category rename, focus returns to the category trigger as the updated controls commit. The menu stays open for continued keyboard management, including when category refresh temporarily disables the field.

Initial scroll restoration runs before paint independently of route focus. Each history entry owns its offset, including repeated visits to the same URL; browser storage availability does not determine restoration. Automatic retries are bounded and stop on wheel, touch, pointer or scroll-key input, including input before hydration. After navigation from the mobile drawer, focus moves to main content only after the drawer releases modal isolation. Refresh and history restoration do not request focus on main content.

Editor resource tabs keep their keyboard selection and focus behavior while a shared background slides between them. Pending scope changes mark the result panel busy and prevent interaction with outgoing content; controls remain available for a newer request. Tab/category/search transitions include empty states, and reduced motion removes both the indicator motion and result animation. Recovery checking after a first draft save is announced in the existing status row without moving the form.

Resolved empty results remain visible during revalidation instead of becoming Loading labels. Editor list/detail switches have one entrance; refresh and saved-ID adoption preserve the current form without replaying it. The initial authenticated form and Markdown preview are server-rendered, with recovery checks and input locking retained during hydration.

## Verification and limits

Playwright runs the desktop Chromium suite and a smaller mobile Chromium project with one worker. Mobile layout checks cover 320, 375 and 768 CSS pixels; populated article/file fixtures exercise long links, tables, code, previews and admin forms. Keyboard workflows cover login, category management, Markdown controls, saving and resource tabs in both themes. axe scans core pages and dialogs in both projects/themes, failing on serious or critical violations. Full scan results, including lesser findings and incomplete checks, are retained with the Playwright report in CI.

Automated scans do not establish complete WCAG conformance. Real-device safe areas, virtual keyboards, browser chrome and assistive-technology announcements still warrant manual acceptance on the intended devices. WebKit, Firefox and screen-reader sessions are not included in this Chromium test matrix. See [testing instructions](testing.md), [editor recovery and navigation behavior](editor.md) and [preference persistence](preferences.md).
